# P-ARG MOB (POAR Inspection) 프로젝트 개발 규칙 및 설계 표준

본 문서는 실제 소스 코드(`src/`, `android/`)와 100% 일치하도록 검증된 프로젝트 공식 개발 규칙입니다.

---

## 1. 코드 스타일 및 TypeScript 아키텍처 규칙

- **들여쓰기**: 스페이스 2칸을 엄수합니다.
- **TypeScript 필수**: 모든 로직 파일은 `.ts`, 컴포넌트는 `<script lang="ts">`를 사용하며 `any` 사용을 최소화합니다.
- **변수 명명 규칙**:
  - 변수/함수: `camelCase`
  - 상수: `UPPER_SNAKE_CASE`
  - 컴포넌트/타입: `PascalCase`
- **JSDoc 및 한국어 주석**: 모든 함수와 인터페이스에는 JSDoc을 작성하고, 비즈니스 로직 설명 주석은 명확한 **한국어**로 기술합니다.
- **빌드 무결성 검증**: 기능 개발 완료 후 반드시 `npm run check`를 실행하여 진단 오류 0건(`0 errors and 0 warnings`)을 유지합니다.

---

## 2. 다국어(i18n) 및 UI/UX 디자인 규칙

- **다국어(i18n) 필수 지원 (하드코딩 금지)**:
  - 본 시스템은 포스코 아르헨티나 현장 전용 앱이므로, 화면의 텍스트나 버튼명을 단일 언어로 하드코딩해서는 안 됩니다.
  - 신규 UI 문구 추가 시 `src/lib/stores/lang.ts`의 사전 객체(`t.ko`, `t.es`)에 **한국어와 스페인어를 동시에 등록**하고, 화면에서는 `$t.yourKey` 형태로 바인딩합니다.
- **라이트 모드 기본 & 다크 모드 전환**:
  - 기본은 주간 시인성을 위한 **라이트 모드**이며, 상단 헤더 메뉴를 통해 다크 모드로 즉시 전환 가능합니다.
  - 네이티브 앱 환경에서는 `SystemBarThemePlugin`과 연동되어 상단 상태바 및 하단 네비게이션바 색상까지 완벽하게 동기화됩니다.
- **Tailwind CSS v4 모듈화**: `@tailwindcss/vite` 엔진을 기반으로 스타일링하며, 공통 카드/버튼 레이아웃은 모듈화하여 관리합니다.
- **터치 디바이스(현장 태블릿/PDA) 최우선**: 마우스 Hover에 의존하지 않으며, 작업 장갑 착용 상태를 고려하여 **최소 터치 타깃 44px 이상** 확보 및 클릭 시 시각적 반응(Active State)을 제공합니다.

## 3. 오프라인 우선(Offline-First) 및 로컬 SQLite 무결성 규칙

- **오프라인 동작 100% 보장**: 네트워크가 완전히 차단된 현장에서도 설비 QR 스캔, 체크리스트 확인, 실적 저장(`tb_mob_rst130`) 등 일상 점검 업무가 지연 없이 로컬 SQLite에서 즉시 수행되어야 합니다.
- **데이터 무결성 최우선 (임의 삭제 금지)**: 통신 오류나 일시적 예외 발생 시 로컬 DB 파일이나 사용자 설정 테이블을 임의로 삭제(`DROP TABLE` 또는 파일 삭제)하지 않고, UI 에러 패널을 통해 안전하게 처리합니다.
- **하이브리드 동기화 파이프라인**: 온라인 복구 시 사용자가 수동 트리거했을 때만 4종 마스터 벌크 UPSERT 및 미송신 실적(`send_flag = 'N'`) 송신을 순차적으로 수행합니다.

## 4. 보안, 화면 캡처 방지 및 세션 수명주기 관리 규칙

- **비밀번호 SHA-256 해시화**: 계정 비밀번호는 평문으로 저장하거나 전송하지 않으며, 클라이언트에서 SHA-256 단방향 해시 암호화 후 보관/전송합니다.
- **화면 캡처 방지 (PrivacyScreen)**: 도면 및 설비 기밀 보호를 위해 일반 점검자 계정 로그인 시 안드로이드 시스템 화면 캡처 및 화면 녹화를 원천 차단합니다. (개발자 계정 로그인 시에만 디버깅용으로 해제)
- **8시간 무활동 감지 자동 로그아웃 (Idle Timer)**: 현장 1개 근무조(Shift) 기준인 8시간(28,800초, `src/lib/stores/activity.ts`의 `IDLE_LIMIT = 28800`) 동안 터치, 키보드, 스크롤 등의 입력이 없을 시 자동으로 세션을 만료시키고 로그인 화면으로 리다이렉트합니다.
- **종료 시 안전 메모리 정리**: 하드웨어 뒤로가기 버튼 2회 터치로 앱 종료 시 인메모리 인증 정보와 SQLite 커넥션을 안전하게 해제(`clearSessionSilent`, `closeDatabase`)합니다.

- **SQLite 엔진 버전 고정 엄수**: 브라우저 및 안드로이드 웹뷰 환경에서 바이너리 SQLite를 구동하는 `jeep-sqlite (2.8.0)` 및 `sql.js (1.11.0)`는 종속성 충돌 방지를 위해 **버전 업그레이드를 절대 금지**합니다.

  - `SystemBarThemePlugin.java`: 상단 상태바 + 하단 네비게이션바 실시간 테마 색상 동기화 전용.

## 8. 버전 관리 및 시맨틱 버저닝(SemVer 2.0.0) 표준

- **버전 단일 진실 공급원 (Single Source of Truth)**:
  - 앱의 버전은 오직 최상단 `package.json`의 `"version"` 필드에서만 단일 관리합니다. (별도의 `.env` 불필요)
  - 웹/스벨트 영역: `src/lib/constants.ts`가 `package.json`을 직접 임포트하여 `PUBLIC_APP_VERSION`으로 앱 전역(스플래시, 다운로드 모달, 설정창)에 자동 전파합니다.
  - 안드로이드 네이티브 영역: `android/app/build.gradle`의 `getAppVersionFromPackageJson()`이 `package.json`을 파싱하여 `versionName`, `versionCode`, 최종 APK 파일명에 자동 주입합니다.
- **시맨틱 버저닝(Semantic Versioning) 원칙 (`MAJOR.MINOR.PATCH`)**:
  - **MAJOR (주 버전, X.0.0)**: 하위 호환성을 파괴하는 대규모 변경 시 증가 (예: SQLite 물리 테이블 스키마 개편, API 통신 규격 전면 교체, 앱 핵심 아키텍처 개편).
  - **MINOR (부 버전, 1.X.0)**: 하위 호환성을 유지하면서 신규 기능이 추가될 때 증가 (예: 신규 점검 메뉴 추가, 다국어 신규 언어 지원, 신규 엑셀 마스터 서식 지원).
  - **PATCH (패치 버전, 1.2.X)**: 기존 동작 규격을 유지하는 단순 버그 수정, 텍스트/UI 스타일 조정, 안정성 및 성능 최적화 시 증가.
- **안드로이드 versionCode 자동 계산 규칙**:
  - 공식: `MAJOR * 10000 + MINOR * 100 + PATCH` (예: `1.2.7` ➔ `10207`).
  - 안드로이드 시스템은 이전 설치본보다 `versionCode`가 큰 경우에만 업데이트 덮어쓰기를 허용하므로, 신규 배포 시에는 반드시 `package.json`의 버전을 상향 조정해야 합니다.
