1. 코드 스타일 및 TypeScript 아키텍처 규칙

  • 들여쓰기: 스페이스 2칸(indentation: 2 spaces)을 엄수합니다.
  • TypeScript 필수: 모든 서비스 로직은 .ts 파일로 작성하고, Svelte 컴포넌트 또한 <script lang="ts">를 사용하여 any 사용을 최소화합니다.
  • 명명 규칙:
    • 변수/함수: camelCase (예: getInspectionTasksByDate)
    • 상수: UPPER_SNAKE_CASE (예: APP_CONFIG, DEV_IDS)
    • 컴포넌트/인터페이스/타입: PascalCase (예: ConfirmModal.svelte, UserSession)
  • JSDoc 및 한국어 주석: 함수, 인터페이스, 서비스 메서드에는 기능과 파라미터, 반환값을 명시하는 JSDoc 주석을 작성하며, 비즈니스 로직 설명 주석은 명확한 한국어로 기술합니다.
  • 빌드 진단 무결성: 작업 완료 시 반드시 npm run check를 실행하여 0 errors and 0 warnings 상태를 유지해야 합니다.

2. 다국어(i18n) 및 UI/UX 디자인 규칙

⚠️ 하드코딩 금지 정책:
본 앱은 포스코 아르헨티나 현장에서 사용되므로 화면의 텍스트, 버튼명, 안내 메시지를 단일 언어로 하드코딩해서는 안 됩니다.
  • 다국어(i18n) 필수 지원: 신규 UI 요소나 문구를 추가할 때는 반드시 src/lib/stores/lang.ts의 언어 사전 객체(t.ko, t.es)에 한국어와 스페인어를 동시에 등록하고, 화면에서는 {$t.yourKey} 형태로 바인딩해야 합니다.
  • 라이트 모드 기본 & 다크 모드 전환: 현장 주간 가독성을 위해 기본은 라이트 모드이며, src/lib/stores/ui.ts 및 SystemBarThemePlugin과 연동하여 상단 상태바 + 하단 네비바까지 시스템 테마가 완벽히 실시간 전환되어야 합니다.
  • Tailwind CSS v4 스타일링: 최신 @tailwindcss/vite 엔진을 기반으로 유틸리티 클래스를 적용하며, 반복되는 카드나 버튼 스타일은 의미 있는 컴포넌트로 모듈화합니다.
  • 터치 디바이스(현장 PDA/태블릿) 최우선: 마우스 Hover 효과에 의존하지 않으며, 작업자가 장갑을 착용한 상태에서도 터치할 수 있도록 최소 터치 타깃 44px 이상 확보 및 클릭 시 확실한 Active 피드백(축소 애니메이션 등)을 부여합니다.

3. 오프라인 우선(Offline-First) 및 로컬 SQLite 무결성 규칙

  • 오프라인 동작 100% 보장: 네트워크 연결이 완전히 끊긴 환경에서도 설비 QR 스캔, 체크리스트 작성, 실적 저장(tb_mob_rst130) 등 모든 일상 점검 업무가 지연 없이 로컬 SQLite에서 즉시 수행되어야 합니다.
  • 데이터 무결성 최우선 (자동 삭제 금지): 통신 에러나 일시적 예외 발생 시 로컬 DB 파일이나 사용자 설정 테이블을 임의로 삭제(DROP TABLE 또는 파일 삭제)하지 않고, UI 에러 패널을 통해 안전하게 예외를 처리해야 합니다.
  • 하이브리드 동기화 파이프라인: 네트워크 연결 복구 시 사용자가 [데이터 수신] 또는 [실적 송신]을 트리거했을 때만 4개 마스터 테이블 벌크 UPSERT 및 send_flag = 'N' 건에 대한 순차 송신을 안전하게 수행합니다.

4. 보안, 화면 캡처 방지 및 세션 수명주기 관리 규칙

  • 비밀번호 SHA-256 해시화: 사용자 비밀번호는 평문으로 저장하거나 전송하지 않으며, 클라이언트에서 SHA-256 단방향 해시 암호화 후 로컬 DB(tb_mob_set020) 보관 및 서버 전송을 수행합니다.
  • 화면 캡처 방지 (PrivacyScreen): 설비 정보 및 점검 데이터 유출 방지를 위해 일반 사용자 계정 접속 시 안드로이드 시스템 화면 캡처 및 화면 녹화를 원천 차단합니다. (개발자 계정 로그인 시에만 디버깅용으로 캡처 방지 해제)
  • 8시간 무활동 감지 자동 로그아웃 (Idle Timer): 현장 1개 근무조(Shift) 기준인 8시간(28,800초, src/lib/stores/activity.ts의 IDLE_LIMIT = 28800) 동안 터치, 마우스, 키보드, 스크롤 입력이 감지되지 않으면 자동으로 세션을 만료시키고 로그인 화면으로 리다이렉트합니다.
  • 종료 시 안전 정리: 하드웨어 뒤로가기 버튼 2회 터치로 앱 종료 시 또는 세션 만료 시, 인메모리 인증 정보와 SQLite 커넥션을 안전하게 해제(clearSessionSilent, closeDatabase)하여 잔류 메모리 오염을 방지합니다.

5. 모바일 UI 알림 및 모달 표준 (ConfirmModal & Toast)

💡 표준 컴포넌트 안내:
모바일 웹뷰 프리징을 유발하는 브라우저 기본 alert(), confirm() 사용은 전면 금지하며, 번들 용량 절감을 위해 외부 무거운 라이브러리(sweetalert2 등) 대신 프로젝트 전용 컴포넌트 및 네이티브 토스트를 사용합니다.
구분 사용 대상 및 표준 구현체 적용 사례
전역 컨펌 / 알림 모달 src/lib/components/ConfirmModal.svelte 동기화 확인/성공/실패, 점검 결과 저장 확인, 저장소 권한 설정 유도 팝업
가벼운 스낵바 토스트 @capacitor/toast (Toast.show) 뒤로가기 버튼 2회 종료 안내 ("한 번 더 누르면 종료됩니다"), 복사 완료 안내
네이티브 시스템 다이얼로그 @capacitor/dialog (Dialog.alert) 웹뷰 렌더링 이전 네이티브 초기화 단계에서의 긴급 안내

6. 라이브러리 및 네이티브 플러그인 관리 원칙

  • SQLite 엔진 버전 고정 엄수: 브라우저 및 안드로이드 웹뷰 환경에서 바이너리 SQLite를 구동하는 jeep-sqlite (2.8.0) 및 sql.js (1.11.0)는 종속성 충돌 방지를 위해 절대 임의로 버전 업그레이드하지 않습니다.
  • 자체 네이티브 플러그인 2종 유지보수:
    • ManageStoragePlugin.java: Android 11+ Scoped Storage 대응용 엑셀 전체 파일 접근 권한 요청 전용.
    • SystemBarThemePlugin.java: 상단 상태바 + 하단 네비게이션바 실시간 테마 색상 동기화 전용.
  • 하드웨어 가속 및 권한: ML Kit 바코드 인식 하드웨어 가속 메타데이터(barcode) 및 카메라 권한, 화면 켜짐 유지(KeepAwake) 설정을 준수합니다.

7. 문서화 및 100% 소스코드 사실 검증 원칙

  • 허위 문서 작성 절대 금지: 존재하지 않는 가상의 쿼리, 미구현된 UI(대시보드 원형 프로그레스 등), 임의의 파일 경로를 문서에 기재하지 않습니다.
  • 문서 단일화 및 실시간 동기화: 모든 아키텍처와 규칙 문서는 docs/문서_허브.html 및 docs/page/ 산하의 통합 포털 체계로 최신 소스코드와 일치하도록 유지합니다.
  • 검증 파이프라인: 문서 작성 후에는 브라우저 렌더링 확인 및 npm run check 진단을 통해 프로젝트의 실제 동작과의 정합성을 최종 검증합니다.

8. 버전 관리 및 시맨틱 버저닝(SemVer 2.0.0) 표준

💡 단일 진실 공급원 (Single Source of Truth):
앱의 버전은 오직 최상단 package.json의 "version" 필드에서만 관리합니다. (.env 파일 완전 불필요)
• 웹/스벨트: src/lib/constants.ts가 package.json을 직접 참조하여 스플래시, 다운로드 모달, 설정 화면에 자동 전파합니다.
• 안드로이드 네이티브: android/app/build.gradle이 package.json을 실시간 파싱하여 versionName, versionCode 및 산출물 APK 파일명에 자동 주입합니다.
구분 증가 규칙 적용 기준 및 구체적 예시

X.0.0		 파괴적 변경
(하위 호환 불가)		 • SQLite 로컬 물리 테이블 스키마의 비호환적 대규모 개편

• 특정 단말기에서의 카메라 바코드 포커싱 예외 보강
• 경미한 버그 픽스 및 성능 최적화
⚠️ 안드로이드 versionCode 자동 계산 공식:
MAJOR * 10000 + MINOR * 100 + PATCH (예: 1.2.7 ➔ 10207)
안드로이드 OS는 이전 설치본보다 versionCode가 반드시 커야만 업데이트 덮어쓰기를 허용하므로, 신규 릴리스 시 package.json의 버전을 필히 상향해야 합니다.
