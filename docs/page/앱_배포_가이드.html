1. 신규 PC 개발 환경 구축 및 초기 세팅 (온보딩 퀵스타트)

새로운 PC에서 프로젝트를 처음 클론받아 개발 및 빌드를 진행하기 위한 사전 필수 소프트웨어 설치 및 초기 설정 절차입니다.

1-1. 사전 필수 소프트웨어 설치

  • Node.js (LTS 버전, v24.x 권장): JavaScript 런타임 및 패키지 관리 도구입니다. 공식 웹사이트에서 LTS 버전을 설치합니다. (설치 후 node -v, npm -v 확인)
  • Android Studio: 안드로이드 SDK, 가상 에뮬레이터 및 빌드 도구를 제공합니다. 공식 홈페이지에서 설치 후 Android SDK (API 34 / Android 14 이상)를 필수로 설치합니다.
  • JDK (Java Development Kit) 17 환경 변수: 안드로이드 Gradle 빌드에 필수입니다. Android Studio 내부의 JBR 폴더를 활용하는 것을 강력히 권장합니다.
    • 시스템 변수 추가: JAVA_HOME = C:\Program Files\Android\Android Studio\jbr
    • 시스템 Path 변수 편집: %JAVA_HOME%\bin 항목 추가
  • VS Code 추천 확장: Svelte for VS Code, Tailwind CSS IntelliSense, ESLint

1-2. 프로젝트 초기 세팅 & SQLite WASM 복사 파이프라인

npm install
💡 자동 복제 파이프라인: npm install 완료 시 postinstall 스크립트가 실행되어 브라우저/안드로이드용 SQLite WASM 바이너리(sql-wasm.wasm)가 static/ 및 static/assets/로 자동 복제됩니다.

5. 시스템 바 네이티브 인셋 및 실시간 테마 동기화 (실제 구현 방식)

💡 가상 코드(웹 Spacer div) 미사용:
본 프로젝트는 웹 레이아웃에 임의의 safe-area spacer div를 삽입하지 않습니다. 대신 안드로이드 네이티브 Window Insets 리스너와 자체 개발한 SystemBarTheme 커스텀 플러그인을 조합하여 상단 상태바 및 하단 네비게이션바를 완벽하게 제어합니다.

A. 네이티브 상/하단 인셋 자동 바인딩 (MainActivity.java)

상단 상태바(statusBars)와 하단 네비게이션바(navigationBars)의 물리적 높이를 시스템으로부터 실시간으로 읽어와 루트 뷰의 Padding으로 자동 적용합니다.

// 1. 투명 상태바/네비바 플래그 해제 및 시스템 바 배경 그리기 활성화
Window window = getWindow();
window.clearFlags(WindowManager.LayoutParams.FLAG_TRANSLUCENT_STATUS);
window.clearFlags(WindowManager.LayoutParams.FLAG_TRANSLUCENT_NAVIGATION);
window.addFlags(WindowManager.LayoutParams.FLAG_DRAWS_SYSTEM_BAR_BACKGROUNDS);

// 2. 상단 상태바 및 하단 네비게이션바 인셋을 네이티브 루트 뷰 패딩으로 동시 자동 바인딩
ViewCompat.setOnApplyWindowInsetsListener(findViewById(android.R.id.content), (v, insets) -> {
    Insets statusBarInsets = insets.getInsets(WindowInsetsCompat.Type.statusBars());
    Insets navBarInsets = insets.getInsets(WindowInsetsCompat.Type.navigationBars());
    v.setPadding(0, statusBarInsets.top, 0, navBarInsets.bottom);
    return insets;
});

B. capacitor.config.json 상태바 비오버레이 설정

"StatusBar": {
  "overlaysWebView": false,
  "style": "DARK"
}

C. SystemBarTheme 커스텀 플러그인을 통한 테마 실시간 동기화

src/routes/+layout.svelte에서 테마 스토어 변경 시 호출되며, 상단 상태바뿐만 아니라 하단 소프트키 네비게이션바의 색상과 아이콘 밝기까지 동시에 동기화합니다.

// src/routes/+layout.svelte 내 호출부
const SystemBarTheme = registerPlugin<SystemBarThemePlugin>("SystemBarTheme");

if (Capacitor.isNativePlatform()) {
  SystemBarTheme.setSystemBarTheme({ isDark }).catch(err => {
    console.warn("[SystemBarTheme] Failed to set system bar theme:", err);
  });
}

6. Scoped Storage 대응 및 ManageStorage 커스텀 플러그인

Android 11+ (API 30+) 환경에서는 엑셀 동기화 파일의 생성/로드뿐만 아니라, 타 앱이나 시스템에 의해 생성된 엑셀 임시 파일을 삭제하기 위해 '모든 파일 관리 권한(All Files Access)'이 필요합니다.

A. AndroidManifest.xml 권한 선언

<uses-permission android:name="android.permission.READ_EXTERNAL_STORAGE" />
<uses-permission android:name="android.permission.WRITE_EXTERNAL_STORAGE" android:maxSdkVersion="28" />
<uses-permission android:name="android.permission.MANAGE_EXTERNAL_STORAGE" />

B. ManageStoragePlugin.java 네이티브 구현 및 동작 원리

권한이 없는 경우 사용자를 안드로이드 시스템의 '모든 파일 관리 허용' 설정 화면으로 직접 안내합니다.

@CapacitorPlugin(name = "ManageStorage")
public class ManageStoragePlugin extends Plugin {
    @PluginMethod
    public void checkPermission(PluginCall call) {
        boolean isApi30OrAbove = Build.VERSION.SDK_INT >= Build.VERSION_CODES.R;
        JSObject ret = new JSObject();
        ret.put("isAndroid11OrAbove", isApi30OrAbove);
        ret.put("granted", isApi30OrAbove ? Environment.isExternalStorageManager() : false);
        call.resolve(ret);
    }

    @PluginMethod
    public void requestPermission(PluginCall call) {
        // ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION 인텐트 호출
        Intent intent = new Intent(Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION);
        Uri uri = Uri.fromParts("package", getContext().getPackageName(), null);
        intent.setData(uri);
        getActivity().startActivity(intent);
        ...
    }
}

  • 키스토어 파일 위치: android/app/release.keystore (Git 형상관리 포함)
  • 실제 서명 Key Alias: posco_arg_mob01
  • 실제 Key/Store 비밀번호: yLN3PpY58DxGmOc5

android/app/build.gradle 내 서명 설정 로직

signingConfigs {
    release {
        storeFile file('release.keystore')
        storePassword localProps['RELEASE_STORE_PASSWORD'] ?: ''
        keyAlias localProps['RELEASE_KEY_ALIAS'] ?: 'posco_arg_mob01'
        keyPassword localProps['RELEASE_KEY_PASSWORD'] ?: ''
    }
}
buildTypes {
    debug {
        // 디버그 빌드도 릴리스 키로 동일 서명 (다른 PC에서 빌드한 APK도 기기에서 업데이트 설치 보장)
        signingConfig signingConfigs.release
    }
    release {
        minifyEnabled false
        proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
        signingConfig signingConfigs.release
    }
}
✅ 상호 호환성 보장: Debug 빌드와 Release 빌드 모두 release.keystore의 단일 릴리스 키로 서명되므로, 다른 PC에서 개발하여 빌드한 APK를 배포하더라도 기존 앱을 삭제할 필요 없이 덮어쓰기 업데이트 설치가 가능합니다.

9. 실제 정기 빌드 워크플로우 (package.json 기반)

WASM 바이너리 복사, 웹 빌드, Capacitor 동기화 및 Gradle 빌드가 원클릭으로 파이프라인화되어 있습니다.

스크립트 명령어 실제 수행 파이프라인 동작 최종 생성 산출물 위치
npm run apk:debug WASM 복사 ➔ Debug 모드 웹빌드 ➔ Cap Sync ➔ Gradle assembleDebug android/apks/app-debug.apk (고정명)
android/apks/app-debug_v1.2.7.apk (버전명)
npm run apk:release WASM 복사 ➔ Release 모드 웹빌드 ➔ Cap Sync ➔ Gradle assembleRelease android/apks/app-release_v1.2.7.apk (원본 미포함본 자동삭제)
npm run apk:all WASM 복사 ➔ Release 웹빌드 ➔ Cap Sync ➔ Debug + Release 동시 빌드 Debug 2종 + Release 1종 전체 자동 수집
npm run app:run 웹빌드 ➔ Cap Sync 후 연결된 실기기 또는 에뮬레이터에서 즉시 설치/실행 단말기 직접 자동 배포
📦 산출물 자동 관리 규칙 (build.gradle):
1. 빌드 시작 시 android/apks/ 폴더를 자동으로 깨끗하게 초기화합니다.
2. Debug 빌드는 버전이 없는 app-debug.apk와 버전이 붙은 app-debug_v1.2.7.apk 두 가지를 모두 복사합니다.
3. Release 빌드는 식별성을 위해 버전이 붙은 app-release_v1.2.7.apk만 유지하고 버전 없는 원본은 자동 삭제합니다.

10. 버전 관리 및 시맨틱 버저닝(SemVer 2.0.0) 배포 규칙

본 프로젝트는 버전의 정합성을 보장하기 위해 최상단 package.json 하나만을 단일 진실 공급원(Single Source of Truth)으로 사용합니다.

💡 버전 단일화 파이프라인 (.env 불필요):
• 버전 입력 위치: 최상단 package.json의 "version" (예: "1.2.7")
• 웹/Svelte 영역: src/lib/constants.ts가 package.json을 직접 참조하여 스플래시, 다운로드 모달, 설정 화면에 자동 전파합니다.
• 안드로이드 네이티브: android/app/build.gradle 내 getAppVersionFromPackageJson()이 versionName, versionCode 및 산출물 APK 파일명에 자동 주입합니다.
• 인앱 자동 업데이트: 서버 version.json의 버전과 앱의 package.json 버전을 비교하여 최신 버전 유무를 판정합니다.

시맨틱 버저닝(Semantic Versioning) 표기 규칙

구분 증가 규칙 적용 기준 및 구체적 예시
MAJOR (주 버전)
X.0.0		 파괴적 변경
(하위 호환 불가)		 • SQLite 로컬 물리 테이블 스키마의 비호환적 대규모 개편
• ERP/MES 서버 통신 API 규격 및 URL 체계 전면 교체
• 앱 인증/세션 아키텍처의 근본적 개편
MINOR (부 버전)
1.X.0		 신규 기능 추가
(하위 호환 유지)		 • 새로운 점검 메뉴 및 대시보드 통계 화면 추가
• 신규 언어 다국어(i18n) 지원 확대 (예: 포르투갈어 추가)
• 신규 엑셀 마스터 서식 파싱 및 출력 지원
PATCH (수 버전)
1.2.X		 패치 / 최적화
(동작 규격 불변)		 • UI 오탈자 수정, 버튼 여백 및 컬러 미세 조정
• 특정 단말기에서의 카메라 바코드 포커싱 예외 보강
• 경미한 버그 픽스 및 성능 최적화
⚠️ 안드로이드 versionCode 계산 공식:
MAJOR * 10000 + MINOR * 100 + PATCH (예: 1.2.7 ➔ 10207)
안드로이드 OS는 이전 설치본보다 versionCode가 반드시 커야만 업데이트 덮어쓰기를 허용하므로, 신규 릴리스 배포 시에는 반드시 package.json의 버전을 필히 상향해야 합니다.

11. 자주 겪는 개발 및 빌드 트러블슈팅

  • "java" 은(는) 내부 또는 외부 명령... 오류가 발생할 때:
    JDK 17 환경 변수(JAVA_HOME)가 지정되지 않았거나 설정 후 터미널/에디터를 재시작하지 않아 발생합니다. 시스템 환경 변수에 JAVA_HOME 등록 및 Path에 %JAVA_HOME%\bin을 추가한 후 VS Code를 완전히 껐다 켜세요.
  • 안드로이드 Build Fail 또는 npm run app:build 에러 발생 시:
    SvelteKit 코드상에 TypeScript 문법 오류나 변수 선언 에러가 존재하는 경우입니다. 터미널에서 npm run check를 실행하여 진단 오류를 먼저 해결하세요.
  • 실기기 연결 시 기기를 찾지 못하거나 오프라인 상태일 때:
    단말기의 USB 디버깅 권한이 승인되지 않은 상태입니다. 스마트폰 [설정] > [개발자 옵션] > [USB 디버깅]을 켜고, PC 연결 시 뜨는 "USB 디버깅을 항상 허용" 팝업을 승인하세요.
