🖥️ 화면 개발 및 유지보수 가이드

스벨트킷(SvelteKit 2)을 처음 접하는 개발자도 실수 없이 기존 화면을 수정하거나 신규 화면을 추가할 수 있도록 정리한 실전 4단계 표준 가이드입니다.

목차 바로가기
0. 개발 전 3대 필수 체크리스트 1. 스벨트킷 라우팅 1분 핵심 2. 신규 화면 생성 실전 4단계 3. 복사해 쓰는 표준 화면 템플릿 4. 공통 UI 조작법 (알림/버튼/이동) 5. 작업 완료 후 최종 검증

0. 화면 개발 시 절대 어기면 안 되는 3대 필수 원칙

🚨 필독: 우리 앱은 포스코 아르헨티나 현장 전용 시스템입니다. 아래 3가지를 지키지 않으면 빌드 에러가 나거나 현장 작업자가 화면을 사용할 수 없게 됩니다.
규칙 지켜야 할 행동 참조 소스 파일
1. 다국어(i18n) 필수 화면에 텍스트("점검 시작", "확인" 등)를 직접 하드코딩 금지 ➔ 반드시 언어 사전에 한국어/스페인어를 동시 등록하고 {$t.yourKey}로 출력 src/lib/stores/lang.ts
2. 라우트 세션 가드 로그인한 점검자만 보는 화면이면 건드릴 필요 없음. 만약 로그인 없이 누구나 열어봐야 하는 화면이면 반드시 화이트리스트에 경로 등록 src/routes/+layout.ts (WHITELIST)
3. 상단 헤더 타이틀 새 화면 진입 시 상단 네비게이션 헤더에 현재 화면명이 올바르게 뜨도록 페이지 진입 시 pageTitle.set(...) 호출 src/lib/stores/ui.ts

1. 스벨트킷(SvelteKit) 라우팅 원리 (초보자 요약)

스벨트킷은 별도의 복잡한 라우터 설정 파일이 없습니다. src/routes/ 아래에 폴더를 만들면 그 폴더 이름이 곧 브라우저 URL 주소가 됩니다.

  • src/routes/notice/+page.svelte ➔ /notice 주소로 열림
  • src/routes/maintenance/+page.svelte ➔ /maintenance 주소로 열림
  • src/routes/maintenance/[id]/+page.svelte ➔ /maintenance/101 (대괄호는 동적 파라미터 ID를 의미)
💡 파일명 규칙: 화면 역할을 하는 파일 이름은 무조건 +page.svelte여야 합니다. (+ 기호 필수)

2. 실전 예제로 따라하는 신규 화면 생성 4단계

예시: "현장 공지사항(/notice)"이라는 새 화면을 추가하는 실전 시나리오입니다.

1 Step 1: 화면 전용 언어팩 생성 (src/lib/locales/notice.ts)

단일 파일에 수백 개 키를 섞지 않고, 화면 전용 사전 파일을 생성하여 한국어와 스페인어를 키 단위로 나란히 등록합니다. (스페인어 누락 시 컴파일 에러 발생)

// src/lib/locales/notice.ts
import { createLocaleStore } from './helper';
import type { Lang } from '$lib/stores/lang';

export const dict = {
  noticeTitle: { ko: '현장 공지사항', es: 'Avisos del Sitio' },
  noticeEmpty: { ko: '등록된 공지사항이 없습니다.', es: 'No hay avisos registrados.' },
  noticeRefresh: { ko: '새로고침', es: 'Actualizar' }
} satisfies Record>;

export const t = createLocaleStore(dict);

2 Step 2: 라우트 폴더 및 +page.svelte 생성

src/routes/notice/ 폴더를 생성하고 내부에 +page.svelte 파일을 만듭니다. (Ctrl+클릭으로 언어팩 즉시 이동 가능)

<script lang="ts">
  import { onMount } from 'svelte';
  import { pageTitle } from '$lib/stores/ui';
  import { t } from '$lib/locales/notice'; // 👈 t 스토어 하나만 깔끔하게 임포트!

  // 화면 진입 시 상단 헤더 타이틀 바인딩
  onMount(() => {
    pageTitle.set($t.noticeTitle);
  });
</script>

<div class="max-w-7xl mx-auto p-4 space-y-4 w-full font-sans">
  <div class="bg-white dark:bg-zinc-900 border border-slate-200 dark:border-zinc-800 rounded-2xl p-6 shadow-sm">
    <h2 class="text-lg font-black text-slate-800 dark:text-zinc-100 mb-2">
      {$t.noticeTitle}
    </h2>
    <p class="text-sm text-slate-500 dark:text-zinc-400">
      {$t.noticeEmpty}
    </p>
  </div>
</div>

3 Step 3: 비로그인 허용 여부 체크 (src/routes/+layout.ts)

로그인한 사용자만 이용하는 일반 업무 화면이라면 아무것도 수정할 필요가 없습니다. (기본 보안 차단 적용됨)

⚠️ 주의 (로그인 전 공개 화면일 때만):
만약 로그인 전에도 접속할 수 있어야 하는 공개 화면이라면, src/routes/+layout.ts의 WHITELIST 배열에 해당 경로를 추가해야 세션 리다이렉트 인터셉트에 걸리지 않습니다. 
// src/routes/+layout.ts (공개 화면일 때만 추가)
const WHITELIST = ['/', '/notice']; // '/notice' 추가

4 Step 4: 다른 화면에서 이동 링크(버튼) 연결

대시보드나 헤더 등에서 해당 화면으로 이동하는 버튼을 만듭니다.

<script lang="ts">
  import { goto } from '$app/navigation';
</script>

<!-- 방법 1: HTML 링크 태그 -->
<a href="/notice" class="text-blue-600 font-bold">공지사항 보기</a>

<!-- 방법 2: SvelteKit JS 함수 이동 (버튼 클릭 이벤트) -->
<button on:click={() => goto('/notice')} class="px-4 py-2 bg-blue-600 text-white rounded-xl">
  공지사항 이동
</button>

3. 복사해서 바로 쓰는 표준 화면 보일러플레이트

새 화면을 만들 때 아래 템플릿 코드를 복사해서 시작하면 헤더 연동, 다크모드, 스크롤 컨테이너 구조가 자동으로 완성됩니다.

<script lang="ts">
  import { onMount } from "svelte";
  import { pageTitle } from "$lib/stores/ui";
  import { lang, t } from "$lib/stores/lang";
  import { dbService } from "$lib/services/database";
  import { showToast } from "$lib/services/toast";

  // 화면 제목 설정
  onMount(() => {
    pageTitle.set(t[$lang].myScreenTitle || "화면 제목");
  });
  $: pageTitle.set(t[$lang].myScreenTitle || "화면 제목");

  let isLoading = false;

  async function handleAction() {
    isLoading = true;
    try {
      // 로직 실행 (예: SQLite 조회나 데이터 처리)
      await showToast("작업이 성공적으로 처리되었습니다.");
    } catch (err: any) {
      alert("오류: " + err.message);
    } finally {
      isLoading = false;
    }
  }
</script>

<!-- 본문 메인 컨테이너 (스크롤 가능 및 모바일 반응형 여백) -->
<div class="max-w-7xl mx-auto p-4 md:p-6 space-y-6 w-full font-sans text-slate-800 dark:text-zinc-100">
  
  <!-- 흰색/다크모드 카드 박스 -->
  <div class="bg-white dark:bg-zinc-900 border border-slate-200/80 dark:border-zinc-800/80 rounded-2xl p-6 shadow-sm space-y-4">
    <h3 class="text-base font-black text-slate-800 dark:text-zinc-100 tracking-tight">
      카드 제목 영역
    </h3>
    <p class="text-xs text-slate-500 dark:text-zinc-400 leading-relaxed">
      설명 문구나 내용이 들어가는 자리입니다.
    </p>

    <!-- 모바일 최적화 터치 버튼 (최소 높이 44px 이상 확보) -->
    <button
      type="button"
      on:click={handleAction}
      disabled={isLoading}
      class="w-full py-3.5 px-4 bg-blue-600 hover:bg-blue-500 text-white font-bold rounded-xl shadow-md transition-all active:scale-[0.98] text-xs cursor-pointer border-none outline-none disabled:opacity-50"
    >
      {isLoading ? "처리 중..." : "확인 및 실행"}
    </button>
  </div>

</div>

4. 자주 쓰는 공통 UI 패턴 (모달, 토스트, 뒤로가기)

A. 가벼운 하단 스낵바 알림 (Toast)

import { showToast } from "$lib/services/toast";

// 하단에 2초간 안내 메시지 출력
await showToast("설정이 저장되었습니다.");

B. 전역 확인/취소 모달 띄우기 (ConfirmModal)

<script lang="ts">
  import ConfirmModal from "$lib/components/ConfirmModal.svelte";

  let isModalOpen = false;

  function onConfirmAction() {
    isModalOpen = false;
    console.log("사용자가 '예'를 눌렀습니다.");
  }
</script>

<button on:click={() => (isModalOpen = true)} class="px-4 py-2 bg-rose-600 text-white rounded-xl">
  데이터 삭제
</button>

<ConfirmModal
  bind:isOpen={isModalOpen}
  title="삭제 확인"
  message="정말로 이 항목을 삭제하시겠습니까?"
  confirmText="삭제"
  cancelText="취소"
  type="confirm"
  on:confirm={onConfirmAction}
  on:cancel={() => (isModalOpen = false)}
/>

C. 이전 페이지로 안전하게 뒤로가기

<!-- 브라우저 / 안드로이드 히스토리 뒤로가기 -->
<button on:click={() => history.back()} class="text-sm font-bold text-slate-500">
  ← 이전 화면으로
</button>

5. 작업 완료 후 필수 검증 명령어 (반드시 실행!)

코드 작성이나 수정을 마쳤다면 터미널에서 다음 명령어를 실행하여 에러가 0건인지 반드시 확인해야 합니다.

명령어 수행 목적 통과 기준
npm run check 타입스크립트 타입 불일치 및 Svelte 구문 검사 svelte-check found 0 errors and 0 warnings 출력
npm run dev 로컬 브라우저 개발 서버 구동 에러 없이 화면이 정상 렌더링되고 다크모드/다국어 전환이 작동하는지 확인
/dev-db (가상 DB) 로컬 SQLite DB 적재 및 쿼리 결과 검증 DEV 계정 로그인 후 우측 하단 플로팅 도구(🛠️) ➔ 실시간 가상 DB 뷰어에서 변경된 테이블 행 데이터 확인
